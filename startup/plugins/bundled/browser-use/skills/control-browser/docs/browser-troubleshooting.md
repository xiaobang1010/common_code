# 浏览器交互排障

- 先使用已选浏览器文档化的 API。不要因为一次页面交互失败就去检查实现源码或更换控制机制。
- 标签过期/缺失/已关闭、受控标签列表为空、或注入的 Playwright 助手不可用，都不能证明浏览器断开。保留现有 `browser` 包装器的重建路径：对受控标签，在专门代码单元返回完整 `browser.tabs.list()` 结果，检视后在下一个调用 `browser.tabs.get(info.id)`；列表为空时新建标签。这是操作前的过晚绑定恢复。
- 当操作可能打开弹窗/新标签且源标签未显示预期效果时，在同一观察单元无条件读取 `browser.tabs.list()` 并打印 `{ controlledTabs }`，让模型从列表做单一决策。不要复用逐步的过晚绑定序列，也不要先返回受控列表再决定下一步。
- 定位器超时、严格模式失败或选择器解析失败后，拍新鲜 `domSnapshot()`。从该快照事实重建唯一定位器，行动前检查 `count()`/`isVisible()`。不要重试同一定位器、猜测不存在的角色/名称/placeholder，或用 `first()`/`last()`/`nth()` 掩盖歧义。
- 只有显式的浏览器断开错误才需要重新选择浏览器并重读其有效文档。若某个文档化成员不可用，使用当前能力清单暴露的替代方案。
- 命令返回「无法附加调试器」类错误时，通常是该网页标签的开发者工具占用了调试通道：提示用户关闭该标签的开发者工具后重试，不要反复重发命令。
